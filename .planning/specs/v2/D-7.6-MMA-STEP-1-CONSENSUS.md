## §2 — STRONG CONSENSUS findings (4/4 panel agreement)

### F-7.6-D-1 [P0 · 5/5 STRONG] — Domain=.racingpoint.cloud cannot share cookie with kiosk.local (eTLD+1 boundary)

**Vote:** qwen P0 0.95 · gemini P0 1.0 · mistral P1 0.85 · mimo P1 0.95 · **r1 P0 0.99** (5/5 across P0/P1 severity)

**Claim:** RCA §4 D specifies `Domain=.racingpoint.cloud` to share staff session across `app.racingpoint.cloud` + `admin.racingpoint.cloud` + `kiosk.local`. But `kiosk.local` is a different eTLD+1 entirely — the Domain attribute cannot share cookies across eTLD+1 boundaries (browser security invariant). Venue kiosks at `kiosk.local` will NOT receive `.racingpoint.cloud` cookies; the architectural assumption is incorrect.

**Mitigation (consensus):** Two options surfaced — (a) migrate kiosks to `kiosk.racingpoint.cloud` subdomain (DNS + nginx + cert work, INFRA scope outside Phase 1), or (b) decouple kiosk auth from staff-cookie sharing (kiosks retain separate auth path; staff cookie scope = `.racingpoint.cloud` cloud-side only). Phase 1 ships (b) — substrate-PR includes explicit comment + acceptance test that kiosk.local case is out-of-scope; INFRA migration tracked separately.

**Disposition:** **ABSORB INTO PR-7.6 Phase 1.** PR body acknowledges kiosk.local out-of-scope; defers kiosk-subdomain migration to V2-PROGRESS-MAP Layer 12 INFRA backlog (new row to file) OR Captain D-7.6-7 disposition.

### F-7.6-D-3 [P0/P1 · 5/5 STRONG] — Cookie duplicate-handling semantics undefined

**Vote:** qwen P1 0.80 · gemini P2 0.90 · mistral P1 0.80 · mimo P2 0.90 · **r1 P0 0.95** (5/5; R1 elevates severity to P0)

**Claim:** RCA §4 B middleware code skeleton (`for part in s.split(';') { ... if let Some(val) = kv.strip_prefix("rp_staff_session=") { return Some(val.to_string()); } }`) returns first match. If browser sends `Cookie: rp_staff_session=A; rp_staff_session=B` (possible via browser bug, proxy mis-config, or attacker-controlled cookie injection), behavior is implicit first-write-wins, which could allow session fixation if attacker can plant cookie before victim's legitimate cookie.

**Mitigation (consensus):** Pick an explicit policy: (a) reject request on duplicate (safest), or (b) last-write-wins per RFC 6265 spirit. Document the choice in code comment + assert via contract test.

**Disposition:** **ABSORB INTO PR-7.6 Phase 1.** Implement (a) reject-on-duplicate — fail-closed semantics. Add unit test asserting middleware rejects request with duplicate `rp_staff_session=` cookies.

## §3 — MAJORITY CONSENSUS findings (3/4 panel agreement)

### F-7.6-D-4 [P0/P1 · 5/5 STRONG] — JWT `exp` claim TTL not aligned with cookie Max-Age

**Vote:** qwen P0 0.95 · gemini P1 0.95 · mistral P1 (in passing) · mimo P2 0.80 · **r1 P1 0.85** (5/5 — all models flagged the JWT/cookie TTL asymmetry)

**Claim:** Cookie hardcoded `Max-Age=1800` (30 min). JWT `exp` claim duration in `auth_staff.rs` minting path is presumably longer (TBD — needs grep). Asymmetry: cookie expires → client re-prompts → JWT still valid server-side → replay window if JWT extracted via earlier XSS or cookie-jar leak.

**Mitigation (consensus):** Align JWT `exp` with cookie Max-Age (30 min) for staff browser path, OR shorten cookie Max-Age, OR implement sliding-window refresh (composes-with F-AMEND-CONS-1 prior consensus, gated on W1-S5 ratification).

**Disposition:** **ABSORB INTO PR-7.6 Phase 1.** Grep current JWT TTL in `auth_staff.rs` mint path; if longer than 1800s, shorten the JWT `exp` for staff-cookie path to match (1800s). Add unit test asserting JWT.exp - JWT.iat == 1800.

### F-7.6-D-6 [P1/P2 · 3/4] — Sub-domain takeover risk via wide `Domain` attribute

**Vote:** mistral P1 0.85 · mimo P1 0.90 · gemini P2 0.85 (via `__Host-` prefix recommendation); 3/4 (qwen did not flag)

**Claim:** `Domain=.racingpoint.cloud` enables ANY subdomain to read the cookie. If a forgotten subdomain (e.g., abandoned `dev.racingpoint.cloud`) is compromised or taken over, attacker can exfiltrate staff sessions. `__Host-` prefix forbids Domain attribute + binds cookie to origin (more secure but precludes multi-origin sharing).

**Mitigation (consensus):** Audit all `racingpoint.cloud` subdomains for control. Phase 1 ships `Domain=.racingpoint.cloud` (per RCA) but adds an explicit audit-by note + Phase 2 sub-task to evaluate `__Host-` prefix vs Domain trade-off. Defer architectural change to Phase 2.

**Disposition:** **DEFER TO PHASE 2.** Phase 1 ships with Domain attribute per RCA + adds subdomain-audit note. Phase 2 sub-PR evaluates `__Host-` migration as kaizen-correct hardening.

### F-7.6-D-7 [P1 · R1-only · NEW] — `HeaderMap::get` returns only first Cookie header; RFC 6265 allows multiple

**Vote:** r1 P1 0.80 (1/5 explicit; others didn't reach this specific axum-internal mechanism)

**Claim:** RCA §4 B middleware uses `headers.get("Cookie")` which returns only the first Cookie header value. Per RFC 6265 and axum HeaderMap semantics, browsers MAY send multiple `Cookie:` headers (rare but spec-permitted; some proxies coalesce, some don't). If `rp_staff_session=` lives in a second/third Cookie header, current code silently fails to extract it.

**Mitigation:** Use `headers.get_all("Cookie")` and iterate, OR document that the request-canonicalization layer (axum or upstream proxy) is expected to merge Cookie headers per RFC 6265 §5.4. Practical risk is LOW (modern browsers send single Cookie header) but spec-completeness gap.

**Disposition:** **ABSORB INTO PR-7.6 Phase 1 as low-priority defensive code.** Use `get_all("Cookie")` iteration. Adds ~5 LOC.
