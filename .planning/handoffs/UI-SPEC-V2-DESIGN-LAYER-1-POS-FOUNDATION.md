### Color rules

- Red is reserved for: brand mark, primary CTA, destructive, fault state. **Never decorative.**
- Amber = pending / warn / latency-above-target. Green = ON / healthy / live. Blue = info / API/endpoint flags.
- All chrome on the `asphalt → dark → card → card-hi` surface stack. **NO gradients on backgrounds.** **NO glassmorphism / neumorphism / claymorphism.**
- DEPRECATED — DO NOT USE: orange `#FF4400` (V1 brand orange — explicitly removed); pre-bundle status palette `#10B981` / `#F59E0B` / `#DC2626` (replaced by bundle's green/amber/red-as-brand).
- DO NOT add purple, teal, or pastel — anything not in this palette is wrong.

### Contrast (WCAG AA verified)

- `--color-rp-ink` (#F2F2F2) on `--color-rp-dark` (#1A1A1A) = 18.2:1 ✓
- `--color-rp-grey` (#5A5A5A) on `--color-rp-dark` (#1A1A1A) = 4.6:1 ✓ (AA passes for body)
- `--color-rp-red` (#E10600) on `--color-rp-dark` (#1A1A1A) = 4.7:1 ✓
- All status colors (green/amber) on rp-dark verified ≥4.5:1 for icon-paired status text.

### Color-only signals BANNED

Every status color MUST be paired with an icon (✓ / ✕ / ⚠ / ⓘ). Color alone is insufficient signal per WCAG AA + CR-3 customer-service-priority + accessibility baseline §3.8.

## Motion

Tailwind transitions only. NO animation library (framer-motion / motion-one / GSAP banned).

| Token | Value | Curve | Use |
|-------|-------|-------|-----|
| `--motion-fast` | 150ms | `cubic-bezier(0.4, 0, 0.2, 1)` | Hover, focus, color change |
| `--motion-std` | 250ms | `cubic-bezier(0.4, 0, 0.2, 1)` | Panel open, dropdown reveal |
| `--motion-slow` | 400ms | `cubic-bezier(0.4, 0, 0.2, 1)` | Modal enter, page transition |
| `--ease-enter` | — | `cubic-bezier(0, 0, 0.2, 1)` | Element entering view |
| `--ease-exit` | — | `cubic-bezier(0.4, 0, 1, 1)` | Element leaving view |

Tailwind utilities allowed: `transition-colors`, `transition-transform`, `transition-opacity`.

**Reduced-motion**: respect `prefers-reduced-motion` — collapse all durations to 0ms.

**NO continuous-loop animations** on POS: no `animate-spin`, no `animate-pulse`, no `animate-bounce`, no hover scale/rotate. Spinner = simple text "Loading..." OR a 3-dot CSS-only stable pulse for waits >500ms. Rationale: POS staff in motion + CR-3 customer-service-priority — animations distract, slow operation, and create false-positive "still loading" perception.

### Cross-screen chrome

**Header (h-16 sticky top, every POS route):**
- Left: `<RacingPointLogo />` (h-10) → links to `/v2/pos`
- Center: page title (h2 style)
- Right: staff badge (name + role) + dropdown (Settings / Logout)

**Footer (status bar, every POS route):**

### State management conventions (Layer 1)

- **Server state**: TanStack Query v5. Query keys: `['cirs', 'lookup', { method, value }]`, `['wallet', customer_id]`, `['sessions', 'active']`. StaleTime: 0 for billing-critical; 60s for menus + reference data. Refetch: 5s active sessions; 10s system status; off for menus.
- **Client state**: useReducer for screen-local state machines (e.g. lookup screen). useState for trivial UI state. Context only for staff-session (one provider at root).
- **URL state**: Next.js searchParams + useSearchParams; ALWAYS canonical (canonicalized phone in URL after lookup).

### Error states (UNIVERSAL across POS screens)

| Error | Render | Recovery |
|-------|--------|----------|
| Network unreachable | Red banner top-of-content; retry button; previous result NOT cleared | Auto-retry every 30s; manual retry |
| 401 (session expired) | Redirect to `/v2/pos/login?return=<current_url>` | Re-auth restores |
| 403 (insufficient role) | Red banner "This action requires manager role" | Manager intervention |
| 404 (resource gone) | EmptyState "Customer not found" / "Order not found" | Back to previous screen |
| 409 (concurrent conflict) | Red banner "Another session is editing this customer; refresh and retry" | Manual refresh |
| 500 (server error) | Red banner "Server error — try again or notify Captain" + error_id | Manual retry |
| Validation error (400) | Inline field error; field highlighted red; submit disabled | Edit and resubmit |

| Register Customer (Path B) | (no confirm — Register is forward-progress, not destructive; idempotent server-side) |
| Logout | (no confirm — trivially reversible by re-login) |

**Do NOT** add "are you sure?" confirms for low-risk reversible actions (anti-pattern #41). Confirms reserved for the 3 irreversible above.

### Toast usage

Toasts are for **background events you should know about**, NOT for "thing you just did" (anti-pattern #45). Acceptable toast triggers:
- Payment success after auto-redirect already happened (rare)
- Network reconnected after interruption
- Session expiry warning (60s before idle timeout)
- Background sync failure (cloud-sync down)

NOT acceptable: success toast after the screen already changed to receipt view.

## Acceptance Criteria

### Per-screen acceptance

Reproduced verbatim from source handoff §5.3 acceptance lists (canonical for executor + checker):

1. **`/v2/pos/login`**: PIN masked as ●●●●; PIN entry via NumPad with backspace + clear; submit calls `POST /api/v1/auth/staff/pin {pin}` → 200 sets HttpOnly cookie + redirect to `/v2/pos`; 401 renders error toast + NumPad clears + focus returns to NumPad; PIN never in DOM/console/network log; tab-order: NumPad → Submit.
2. **`/v2/pos`**: Active sessions render <500ms of route entry; polling refresh 5s without UI flash (`keepPreviousData`); Quick Actions ≥48px touch targets; System Status surfaces ANY anomaly visibly (red dot + name); on network failure, stale data shown with "Last updated: Xs ago" banner — no auto-redirect.
3. **`/v2/pos/lookup`**: Phone entry via NumPad OR keyboard; canonicalize debounce 300ms; Lookup CTA disabled while input empty; Indian-mobile-prefix WARN inline below input on first non-{6,7,8,9} 10-digit input; Found <500ms p95; NotFound CTA preserves canonicalized phone in query; InvalidPhone red banner + retain input; AmbiguousPhone amber banner + override; network error red banner + retry + previous result NOT cleared; Walk-In Guest 1/2 short-circuit (no API call needed); Bind Identity routes to `/v2/pos/session/...` or dashboard.
4. **`/v2/pos/register`**: Phone read-only (canonical from query); name required min 2 chars; email optional but validated when provided; DOB free-text input acceptable for V2.0; submit success routes to top-up flow with `?just_registered=true` banner; submit failure shows error toast + form retained.
5. **`/v2/pos/topup/[customer_id]`**: Amount input accepts whole rupees (paise = ₹X * 100; UI displays ₹X); tier-ladder updates <200ms of input change; tax invoice number generated server-side; confirmation button label includes exact amount ("Confirm Payment ₹500.00"); after confirm, success state shows receipt + auto-print prompt (browser print dialog); on payment failure error toast + form retained; audit invariant — every successful top-up writes to `wallet_topups` table.
6. **`/v2/pos/cafe`**: NO "Use Credits" / "Pay from Wallet" button anywhere on cafe surface (CR-5 enforcement); delivery toggle gaming_hall (default per Q-S6 Opt C) vs cafe_seating; anonymous orders allowed; phone lookup optional; if provided + Found, order attaches for retroactive-mapping; order submission triggers chef display update.
7. **`/v2/pos/billing`**: PS5 session start/end manually entered (no auto-detect — V2.1 scope); pending payment list sorted oldest-first; >7 days amber, >30 days red; mark-paid irreversible w/ confirm dialog; apology credits list read-only.
8. **`/v2/pos/session/[session_id]`**: Mid-session top-up preserves session id in query param; apology credit modal with reason categories (Game crash / Hardware fault / Network outage / Other) + amount input + confirm + audit row written; end session confirms total bill (Way A additive) + writes `session_ended_at` + routes to dashboard.
