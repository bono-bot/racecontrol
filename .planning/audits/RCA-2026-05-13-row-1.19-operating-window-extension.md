## 4. V2-alignment delta

What the boundary **should** look like under V2 doctrine (V2-MASTER-STATE canonical-source ledger + `project_v2_customer_workflows_consolidated_20260503` + DoD §3.1 14:00 customer-day anchor + DoD L29 12:00-24:00 + DoD L33 Tail extension):

**A. Canonical-clock contract.** V2 establishes **`GET /api/v1/operating-window`** as the single-source-of-truth operating-window endpoint, returning:

```json
{
  "is_open": bool,                  // clock-based: 12:00 ≤ IST_hour < 24:00 OR extension_active
  "current_time_ist": "HH:MM:SS",   // IST wall-clock (UTC+5:30 explicit math)
  "current_time_utc": "ISO8601",    // UTC reference for cross-tz drift detection
  "business_hours": { "open": "12:00", "close": "24:00" },  // DoD L29 locked
  "tail_active": bool,              // 23:00 ≤ IST_hour < 24:00 OR > 24:00 wrap
  "extension_active": bool,         // tail_active AND iracing_active
  "iracing_active": bool,           // ≥1 pod has iRacing telemetry in last 60s
  "iracing_active_pods": [int],     // pod_number list (for staff visibility)
  "source": "racecontrol-canonical" // organ identifier (cross-organ disambiguation)
}
```

**B. Cross-organ canonical-clock.** All organs (whatsapp-bot, PWA, kiosk, admin) consume `GET /api/v1/operating-window` rather than computing IST window state locally. DoD L29 citation moves from "whatsapp-bot/src/services/istTimeService.js" (V1) to "racecontrol /api/v1/operating-window (canonical-emitter); whatsapp-bot/src/services/istTimeService.js (deprecated, kept for 30-day-soak)".

**C. Settings substrate.** V2 moves `business_hours_start='12:00'` + `business_hours_end='24:00'` to a **v2-config canonical source-of-truth** (single migration file, NOT a duplicate of V1 `kiosk_settings` defaults). Pattern: same as Wallet Framing C single-purpose voucher anchor that lives in `v2-skeleton/05-definition-of-done.md` and is read from there, NOT re-encoded per-table.

**D. iRacing extension derivation.** V2 substrate-PR adds:
- Fleet-aggregation field at `crates/racecontrol/src/api/fleet_health_api.rs` → `iracing_active_count: u32` derived from per-pod `last_iracing_telemetry_at` within 60s window
- `GET /api/v1/operating-window` reads this aggregation; sets `iracing_active: count > 0`
- DoD L33 Tail semantic: `extension_active = tail_active && iracing_active`

**E. Clock-injection seam.** V2 operating-window handler refactors to:
```rust
pub async fn get_operating_window(State(state): State<Arc<AppState>>) -> Json<Value> {
    let now = state.clock.now_ist(); // injectable via AppState; default = explicit UTC+5:30 math
    compute_window_state(now, &state.config.business_hours, fleet_iracing_active(&state).await)
}
```
Pure function `compute_window_state(now, business_hours, iracing_active)` is callable from both handler and test; `state.clock` is a trait object swappable in tests.

**F. Deprecation timer.** V2 keeps `GET /api/v1/scheduler/status` as V1-anchor for 30 days post-`/operating-window` ship; logs deprecation warning on every call; removed at +30d. Same pattern as Wave-1 W1 cloud_sync legacy endpoint sunsets.

**Named gap (R1):** No V2 cross-organ canonical-clock contract exists today. All four V2 organs duplicate the IST window logic with no shared source-of-truth. This RCA's substrate PR closes the racecontrol leg; bilateral PR closes whatsapp-bot + PWA + kiosk legs.
