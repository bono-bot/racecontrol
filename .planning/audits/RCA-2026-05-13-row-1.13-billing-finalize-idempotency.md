## 4. V2-alignment delta

V2 `/api/v1/billing/finalize` unified endpoint:

```
POST /api/v1/billing/finalize
{
  "session_id": "...",
  "reason": "CustomerStop" | "AgentShutdown" | "AutoComplete" | "VenueClosed",
  "idempotency_key": "...",
  "actor": "kiosk" | "staff" | "rc-agent" | "auto-scheduler"
}

→ 200 {
  "session_id": "...",
  "finalized_at": "ISO8601",
  "finalize_reason": "...",
  "wallet_debit_paise_final": int,
  "wallet_refund_paise": int,
  "session_duration_secs": int,
  "idempotency_status": "first" | "replayed"
}
```

**Semantic guarantees:**
- **Single-source-of-truth.** All finalize requests (kiosk customer-stop, staff override, rc-agent crash-recovery, scheduler auto-end) flow through this endpoint. Auth-tier set per `actor` field (kiosk + staff = staff-JWT; rc-agent = service-key; auto-scheduler = internal).
- **Idempotent.** `idempotency_key` UNIQUE-stamped to `billing_sessions.finalize_idempotency_key`; replay returns first-call's result row with `idempotency_status: "replayed"`. Pattern matches `billing_start.rs:100,259,307` + `billing_invoice.rs:257-369`.
- **1s SLA observability.** `tracing` span `billing.finalize` wraps end-to-end; emit `finalize_latency_ms` histogram; alert on p95 > 1000ms.
- **State-transition matrix.** `from_status ∈ {active, paused_manual, paused_game_pause, paused_disconnect, paused_crash_recovery, waiting_for_game}` → finalize OK. `from_status ∈ {finalized, refunded, cancelled}` → 409 conflict with `idempotency_status: "terminal"`.
- **Concurrent-finalize defense.** `BEGIN IMMEDIATE` SQLite transaction around session row update; second caller blocks then reads finalized state; returns 409 with replay status.
- **F-05 invariant preserved.** wallet_debit_paise SELECT-before-UPDATE pattern (column-snapshot) explicitly tested + comment-anchored.
- **Cloud_sync verify-after-finalize.** Per §S-242 cloud_sync Phase 1 verify-by-construction, finalize calls `cloud_sync_verify::verify_push(..)` to confirm row landed at Bono VPS mirror before returning success to caller.

**V1 endpoints retained 30 days:**
- `POST /billing/{id}/stop` → internally calls `finalize(reason: CustomerStop, actor: staff)` + adds `Deprecation: 2026-06-13` header
- `POST /billing/{id}/stop-service` → calls `finalize(reason: CustomerStop, actor: rc-agent)`
- `POST /billing/{id}/agent-shutdown` → calls `finalize(reason: AgentShutdown, actor: rc-agent)`

**Named gap (R4):** V1 idempotency_key handling is per-endpoint-discretion. V2 establishes a doctrine: every state-changing endpoint that customers can replay (start, stop/finalize, refund, top-up) MUST honor idempotency_key with DB stamp + SELECT-by-key dedupe. Apply doctrine retroactively when authoring this RCA's sibling RCAs.
