# §S-146 V1↔V2 RCA — Row 1.11 telemetry-pulse + billing/active shape

## 1. Boundary map

Two related substrate gaps surfaced by §S-216 iter2 race-telemetry-leaderboard contract test:

**A. Telemetry pulse endpoint (missing)**
- `/api/v1/telemetry/pulse` — **DOES NOT EXIST** (grep 0 hits across `crates/racecontrol/src` + `crates/rc-agent/src`)
- Intended semantic: "is telemetry actively flowing on pod X within the last N seconds?" — a pod-level liveness probe for the race-leaderboard organ
- V1 alternative: caller infers from `fleet_health` last_seen + ws_connected, but these are agent-process-level signals, NOT sim-telemetry-level signals; a pod can have ws_connected=true and zero telemetry flowing (game crashed, AC paused, agent alive but sim silent)

**B. fleet_health last_telemetry_at field (missing)**
- `crates/racecontrol/src/api/fleet_health_api.rs` — exposes `PodFleetStatus`; check for `last_telemetry_at` field: **ABSENT**
- Reachability fields (`ws_connected`, `http_reachable`, `last_seen`) are at the AGENT layer; sim-telemetry liveness needs its own field

**C. /billing/active BillingSessionInfo shape**
- `crates/racecontrol/src/api/routes.rs:518` — `/billing/active` GET handler `active_billing_sessions`
- `crates/racecontrol/src/api/billing_views.rs:328` — handler path; returns `Vec<BillingSessionInfo>`
- `crates/rc-common/src/types.rs:466` — `BillingSessionInfo` struct: contains session-level fields (id, driver_id, driver_name, pod_id, pricing_tier_name, allocated_seconds, driving_seconds, remaining_seconds, status, driving_state, started_at, split_count, billing_mode, cost_paise, ...) but **does NOT contain `current_lap`, `last_lap_time_ms`, `best_lap_time_ms`** (per §S-216.5 row 1.11 shape-gap)
- Lap data lives in a SEPARATE struct (`rc-common/src/types.rs:257-259` `best_lap_ms` + `current_lap_invalid`; line 317-318 `last_lap_ms` + `best_lap_ms`) — caller must JOIN `/billing/active` × `/sessions/{id}/laps` to get a live race-state view

**D. Existing telemetry plumbing**
- `crates/rc-agent/src/sims/*.rs` — per-sim telemetry parsers (AC, iRacing, F1_25, AMS2, LMU, Forza); emit lap events + position events
- `crates/racecontrol/src/ws/*.rs` — WS receiver for telemetry events; persists laps to DB
- No "telemetry pulse" emission — agents emit DATA events but not LIVENESS events

**Contract test scaffolded:** `racecontrol/tests/contract/race-telemetry-leaderboard.spec.ts` (§S-216 iter2) — env-gated SKIP `V1_NO_TELEMETRY_PULSE` + `V1_NO_LAP_FIELDS_ON_BILLING_ACTIVE`.

## 4. V2-alignment delta

**A. Telemetry pulse primitive.** V2 establishes `last_telemetry_at: Option<DateTime<Utc>>` on `PodFleetStatus` + emits per-pod-per-sim heartbeat:
- rc-agent `sims/*.rs` emit `TelemetryPulseEvent { pod_number, sim, last_packet_at }` every 15s while telemetry channel is open (independent of data interestingness)
- racecontrol WS receiver updates `fleet_state.pods[N].last_telemetry_at`
- `GET /api/v1/fleet/health` exposes the field; cross-organ consumers (leaderboard, admin, PWA) read it

**B. `/api/v1/telemetry/pulse` endpoint.** V2 adds dedicated read-only endpoint:
```
GET /api/v1/telemetry/pulse → [
  { pod_number: 3, sim: "AC", last_packet_at: "ISO8601", pulse_age_seconds: 12, pulse_alive: true },
  ...
]
GET /api/v1/telemetry/pulse?pod_number=3 → single-pod variant
```
- Read-only; safe for organ-level polling (1Hz)
- Public route (no JWT); same auth-tier as `/health`

**C. BillingSessionInfo lap-time fields.** Migration ALTER `BillingSessionInfo` struct:
- `current_lap_number: Option<u32>` — lap index (0-indexed from session start)
- `current_lap_time_ms: Option<u32>` — wall-clock time elapsed in current lap (from sector boundary or session start)
- `last_lap_time_ms: Option<u32>` — most-recent-completed lap duration
- `best_lap_time_ms: Option<u32>` — fastest-lap duration in this session
- All fields Option<> for old-client compat (§S-242 doctrine)
- Populated by `BillingTimer::to_info()` reading session's lap-tracker state

**D. Migration covers all consumers.** Per `racecontrol/CLAUDE.md` DB-migrations standing rule:
- venue racecontrol.db: ALTER active_billing_sessions VIEW or rebuild BillingSessionInfo serialization
- Bono VPS cloud_data_sync_v2 mirror: matching ALTER if cloud_sync caches BillingSessionInfo (per §S-242 cloud_sync cursor doctrine)
- TypeScript shared-types regen (`crates/racecontrol/src/bin/gen_types.rs` covers; line 117)

**Named gap (R3):** V1 had no signal-for-liveness primitive at sim layer (only agent layer). V2 introduces "telemetry pulse" as the sim-layer liveness primitive. The R3 substrate decision: pulse lives on the existing WS channel (additive `TelemetryPulseEvent`), not a new transport.
