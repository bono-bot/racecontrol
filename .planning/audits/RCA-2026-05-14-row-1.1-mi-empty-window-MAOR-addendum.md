### §3.2 — IMPORTANT: SQL schema lacks UNIQUE(window_start_utc) constraint (CONF 85)

**Defect:** Parent RCA §4A schema (L82-93) has `id TEXT PRIMARY KEY` (implicit index) but no `UNIQUE` constraint on `window_start_utc`. Phase 2 detector loop runs on 60s tokio::time::interval; if server restarts between ticks or interval drifts, two emit calls could land for overlapping 5-min windows. Spec test L276-283 asserts "no two events share identical window_start" — but with different UUIDs the application-only dedup would not violate the PRIMARY KEY constraint. DB-layer invariant absent.

**Corrective action (proposed for Phase 1 substrate PR, awaiting D-1.1-1 ratify):**
```sql
CREATE TABLE mi_empty_window_events (
    id TEXT PRIMARY KEY,
    window_start_utc TEXT NOT NULL,
    window_end_utc TEXT NOT NULL,
    window_duration_minutes INTEGER NOT NULL,
    occupancy_pct REAL NOT NULL,
    occupied_pod_count INTEGER NOT NULL,
    fleet_size INTEGER NOT NULL,
    detected_at_utc TEXT NOT NULL,
    severity TEXT NOT NULL,
    UNIQUE(window_start_utc)  -- NEW: DB-layer dedup invariant per MAOR §3.2
);
```

Alternative (if rolling-window overlap is intentional for Phase 2 sustained-dip detector): explicitly document in RCA that window dedup is application-enforced only, with rationale.

### §3.3 — IMPORTANT: SQL column names diverge from spec test EmptyWindowEvent interface (CONF 90)

**Defect:** Parent RCA §4A SQL uses `window_start_utc / window_end_utc / occupied_pod_count / detected_at_utc`; spec test `EmptyWindowEvent` interface at mi-empty-window-detection.spec.ts L157-169 expects `window_start / window_end / empty_pod_count / ts`. Three column-name conflicts + one inversion (occupied vs empty count). Implementation would need ad-hoc rename layer at API serialization OR migration revision before Phase 1 ships.

**Reconciliation (proposed; defers to Captain Q-MI-D in §4 decision queue):**

| `window_start_utc` | `window_start` | `window_start_utc` (DB) + `window_start` (API JSON) | Drop `_utc` suffix at API JSON layer per `content_drift_events` convention (detected_at field, no `_utc` suffix in API response); DB stores UTC strings with explicit suffix; serializer omits suffix |
| `window_end_utc` | `window_end` | `window_end_utc` (DB) + `window_end` (API JSON) | Same as above |
