# §S-146 V1↔V2 RCA — Row 1.19 Operating window 12:00–24:00 IST + iRacing extension

## 1. Boundary map

The V1↔V2 boundary on operating-window exists at three concrete code surfaces in `crates/racecontrol/`:

**Surface S-1.19-A: `crates/racecontrol/src/scheduler.rs:28-29` — V1 default open/close hours in scheduler tick**
```rust
let open = get_setting(state, "business_hours_start").await.unwrap_or_else(|| "10:00".into());
let open_time = NaiveTime::parse_from_str(&open, "%H:%M").unwrap_or(NaiveTime::from_hms_opt(10, 0, 0).unwrap());
```
- V1 default = `"10:00"` (open) / `"22:00"` (close)
- DoD `comms-link/v2-skeleton/05-definition-of-done.md` L29 verbatim: *"Racing Point operating window per the locked venue hours: 12:00–24:00 IST, daily (source: whatsapp-bot/src/services/istTimeService.js)."*
- 4-hour delta on close (22:00 vs 24:00) + 2-hour delta on open (10:00 vs 12:00) = 6h/day of V1 disagreement with DoD canonical

**Surface S-1.19-B: `crates/racecontrol/src/scheduler.rs:307-367` — `get_status` handler emits `is_open` boolean using same V1 defaults**
```rust
let open = get_setting(&state, "business_hours_start").await.unwrap_or_else(|| "10:00".into());
let close = get_setting(&state, "business_hours_end").await.unwrap_or_else(|| "22:00".into());
// ...
let is_open = time_now >= open_time && time_now < close_time;
```
- Uses `chrono::Local::now()` (line 308) — on Server .23 Windows this resolves to IST (Asia/Kolkata system TZ); on Bono VPS Linux this resolves to UTC. **Cross-pilot drift class — same code returns different `is_open` on the two deployment targets.**
- Response shape: `{enabled, current_time, is_open, business_hours.{open,close}, settings, active_sessions, upcoming_bookings, recent_events}` — no `extension_active`, no `iracing_active`, no ISO-format current_time, no DPDP-clean separation (response includes upcoming_bookings which carries booking IDs).

**Surface S-1.19-C: `crates/racecontrol/src/api/routes.rs:653` — V1 endpoint registration under staff-JWT gate**
```rust
.route("/scheduler/status", get(scheduler::get_status))
```
- Route sits inside the `protected_routes` staff-JWT section (line 652 "Scheduler" comment block before staff/shift-handoff). Customer-facing surfaces (PWA, kiosk customer view) cannot read venue-open state from this endpoint without a staff JWT — V1 antipattern for a public venue-state signal.

**Surface absences (V2 doctrine requires; V1 lacks):**
- `extension_active: bool` field — absent (G-1.19-2)
- `iracing_active: bool` field — absent (composes-with G-1.19-2)
- `GET /api/v1/operating-window` canonical V2 endpoint — absent (G-1.19-3); V1 `/scheduler/status` is the inferred substrate
- ISO-8601 IST `current_time` with `+05:30` offset — absent (V1 emits `HH:MM` string format only)
- DPDP-clean response shape (no booking IDs, no customer data on a venue-state read) — V1 emits upcoming_bookings IDs

**DB-side:**
- `kiosk_settings` table holds `business_hours_start` / `business_hours_end` (V1 schema)
- No `operating_window_v2` table; no canonical "DoD-verbatim" source — DoD spec doc is the only source-of-truth
- No `extension_active` column; no iracing-session pointer
