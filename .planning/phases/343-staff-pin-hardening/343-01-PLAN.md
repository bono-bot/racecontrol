<objective>
Block silent PIN-revert by making cloud sync authority explicit at the API layer. When the venue instance receives a mutation for a cloud-authoritative table, return HTTP 409 with the cloud URL instead of silently accepting the write that will be overwritten within 30s.

Purpose: Prevent the exact failure mode observed in the Vishal 2026-04-09 incident — venue PUT /staff/{id} returns 200, then cloud sync overwrites the change within one sync tick.
Output: Venue rejects staff mutations with 409 + clear cloud_url redirect. Cloud accepts them. Emergency override available.

    **Part A — Define a shared guard helper at module level near the staff handlers:**
    ```rust
    fn guard_cloud_authoritative(
        state: &Arc<AppState>,
        table: &str,
        id: &str,
    ) -> Option<(StatusCode, Json<Value>)> {
        if crate::config::allow_venue_staff_write() {
            return None; // emergency override
        }
        if crate::config::this_instance_is_cloud(&state.config) {
            return None; // we ARE the authoritative writer
        }
        if !state.config.cloud.is_cloud_authoritative_for(table) {
            return None; // table is not in the list
        }
        let cloud_url = format!("{}/staff/{}", state.config.cloud.api_url.trim_end_matches('/'), id);
        Some((
            StatusCode::CONFLICT,
            Json(json!({
                "error": format!("{} is cloud-authoritative on this instance", table),
                "cloud_url": cloud_url,
                "hint": "Submit your change to the cloud endpoint. It will sync to venue within ~30s.",
                "override_hint": "Emergency: set RC_ALLOW_VENUE_STAFF_WRITE=1 on the venue instance and restart.",
            })),
        ))
    }
    ```
