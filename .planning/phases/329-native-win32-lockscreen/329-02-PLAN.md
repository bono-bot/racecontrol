<objective>
Add interactive lock screen states: PIN entry with keyboard handling, QR code display, and ActiveSession countdown timer. This plan makes the native lock screen functionally equivalent to the Edge version for the core customer journey (scan QR / enter PIN -> see timer -> session ends).

Purpose: These are the three states customers interact with most. PIN entry is the highest-risk component (keyboard focus management on pods with ConspitLink competing for input). ActiveSession timer is the most visible (customers watch it the entire session).

Output: keyboard.rs (PIN input handling), qr.rs (QR GDI renderer), updated painter.rs with paint functions for PinEntry, QrDisplay, and ActiveSession states.
</objective>

  <behavior>
    - PIN buffer accepts digits '0'-'9', max 6 chars
    - Backspace removes last digit from buffer
    - Enter on 4+ digit buffer triggers PinEntered event
    - Auto-submit: reaching 6 digits triggers PinEntered without Enter
    - Characters outside '0'-'9' are ignored
    - Backspace on empty buffer is a no-op
    - QR code renders with correct module count for a given payload string
  </behavior>
  <action>
    1. Create `crates/rc-agent/src/lock_screen/keyboard.rs`:
       - `pub struct PinInputState { pub buffer: String, pub max_len: usize }` — tracks current PIN input
       - `impl PinInputState`:
         - `pub fn new() -> Self` — empty buffer, max_len = 6
         - `pub fn push_digit(&mut self, ch: char) -> bool` — if '0'-'9' and len < max_len, push and return true
         - `pub fn pop(&mut self) -> bool` — remove last char, return true if removed
         - `pub fn is_complete(&self) -> bool` — len >= 4 (submittable) — but auto-submit only at 6
         - `pub fn is_full(&self) -> bool` — len == max_len
         - `pub fn take(&mut self) -> String` — take buffer contents, reset to empty
         - `pub fn display_dots(&self) -> String` — returns "● " repeated for each digit (for rendering)
         - `pub fn clear(&mut self)` — reset buffer
       - `pub fn handle_wm_char(ws: &mut LockWindowState, ch: char) -> bool` — called from wnd_proc on WM_CHAR:
         - If current state is PinEntry, and ch is '0'-'9': push to pin_input buffer stored in LockWindowState (add `pin_input: PinInputState` field to LockWindowState in window.rs)
         - If buffer reaches 6 digits (is_full), auto-submit: `ws.event_tx.blocking_send(LockScreenEvent::PinEntered { pin: ws.pin_input.take() })`
         - Return true if handled (to signal InvalidateRect needed)
       - `pub fn handle_wm_keydown(ws: &mut LockWindowState, vk: i32) -> bool` — called from wnd_proc on WM_KEYDOWN:
         - VK_BACK: pop from buffer, return true
         - VK_RETURN: if buffer.len() >= 4, submit PIN and return true
         - Otherwise return false
       - Write unit tests in same file (`#[cfg(test)] mod tests`):
         - Test digit push, overflow at 6, backspace, auto-submit detection, take+reset, display_dots output

    2. Create `crates/rc-agent/src/lock_screen/qr.rs`:
       - `pub unsafe fn paint_qr_code(hdc: HDC, qr_data: &str, center_x: i32, center_y: i32, module_size: i32)` — following the exact pattern from 329-RESEARCH.md Example 4:
         a. `QrCode::new(qr_data.as_bytes())` — if Err, log and return (no panic)
         b. Get modules via `code.to_colors()` and `code.width()`
         c. Calculate total size and start position for centering
         d. Draw white background rect (quiet zone = 1 module_size border)
         e. Iterate modules, `FillRect` with black brush for Dark pixels
         f. CRITICAL: Create brushes (white_brush, black_brush) at start, `DeleteObject` both at end — do NOT leak GDI handles
       - Below the QR code, render the qr_data URL as small text (font_small, grey) so staff can read it if QR scan fails

    3. Update `lock_screen/mod.rs`:
       - Add `pub mod keyboard;` and `pub mod qr;`
       - Re-export `pub use keyboard::PinInputState;`
