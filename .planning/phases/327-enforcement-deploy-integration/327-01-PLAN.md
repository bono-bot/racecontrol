  <action>
Create a PostToolUse hook at ~/.claude/hooks/screenshot-enforce.js that:

**1. Tracks frontend file modifications (per HOOK-02):**
- On every PostToolUse event for Write/Edit/Bash tools, check if the tool_input contains a file path matching frontend patterns
- Frontend patterns: files ending in `.tsx`, `.ts` (but NOT in `crates/`), `.css`, `.scss`, or files containing paths `web/`, `kiosk/`, `apps/`, `pwa/`
- Exclude: files in `crates/`, `scripts/`, files ending in `.rs`, `.sh`, `.bat`, `.toml`, `.json` (config), `tests/` directory
- Track state: write `{session_id}-screenshot-state.json` to `~/.claude/cgp-state/` with `{ frontendEdited: true, lastEditTime: timestamp, editedFiles: [...] }`

**2. Detects completion claims (per HOOK-01):**
- Parse stdin JSON for the assistant's output text (check `tool_input` and surrounding context)
- Actually, PostToolUse receives the RESULT, not future text. The better approach:
- Use the hook to inject additionalContext as a WARNING when frontend files have been edited but no screenshot exists yet
- On every PostToolUse call: if state shows `frontendEdited: true`, check for screenshot evidence
- If no screenshot evidence found, output additionalContext warning: "SCREENSHOT ENFORCEMENT: You modified frontend files ({list}). Before claiming fixed/done/resolved, capture screenshots via `npx playwright test --config tests/page-crawler/playwright.config.ts --grep '{app}'` or `npx playwright test --config tests/visual-regression/playwright.config.ts`. No screenshot evidence found yet in tests/screenshots/."

**3. Checks for screenshot evidence (per HOOK-03):**
- Scan `tests/screenshots/` directory recursively for `.png` files
- Compare file mtime against `lastEditTime` from state
- If any screenshot is newer than the last frontend edit, mark `screenshotCaptured: true` in state and stop warning
- Also check `tests/visual-regression/__screenshots__/` for updated baselines

**4. Error handling:**
- On any error (missing directory, corrupt state, etc.), allow silently (exit 0, no output)
- Use try/catch around all fs operations
- State file cleanup: include `createdAt` timestamp, cgp-cleanup.js already handles stale files

**Implementation notes:**
- Read stdin synchronously with `fs.readFileSync(0, 'utf8')` (matches backlog-enforce.js pattern)
- Parse stdin as JSON, extract `tool_name`, `tool_input`, `session_id`
- PostToolUse output format: `{ hookSpecificOutput: { hookEventName: "PostToolUse", additionalContext: "..." } }`
- State directory: `path.join(os.homedir(), '.claude', 'cgp-state')`
- Keep the hook fast (< 100ms) -- no async operations, no network calls
