## Prompt scope (the diff under review)

The audit evaluates the TOTAL diff produced by Plans 01-07:
- Plan 01: New server route `GET /api/v1/pods/mesh-service-key` pod-IP gated + POS .130 reclassified as Pod
- Plan 02: rc-agent mesh_key_cache module (MeshKeyCache, fetch_from_server, get_key_or_env)
- Plan 03: rc-agent main.rs wiring (boot-time initial fetch + spawn_periodic_refetch @ 300s)
- Plan 04: 3 consumer rewires (ai_debugger, remote_ops middleware, ws_handler csv fallback) — all read cache first, env fallback
- Plans 05+06+07: deploy-server.sh 3 factor fixes (8-task schtasks, OTA_DEPLOYING sentinel, WMIC commandline kill)

## Questions each model must answer

1. **Auth boundary:** does pod-IP gating on `/pods/mesh-service-key` plus the `require_pod_source` fail-closed middleware adequately bound the secret? Consider attack surface: customer WiFi spoofing, Tailscale traffic, cloud requests.
2. **Cache semantics:** is "server explicit empty → cache None (overwrite)" vs "network fail → preserve last-known-good" a correct split? What if server is reachable but its TOML key accidentally gets wiped?
3. **Race/lock:** any lock-across-await in mesh_key_cache.rs? Any deadlock risk between remote_ops middleware reading cache and the periodic refetch writing cache?
4. **Test coverage:** do the 9 mesh_key_cache tests + preserved 7 remote_ops service-key tests constitute sufficient coverage?
5. **Deploy script:** do Plans 05+06+07 close the 3 abort factors without introducing new ones? Is WMIC the right cross-version choice? Is OTA_DEPLOYING sentinel cleanup guaranteed in all error paths?
6. **Cross-process:** is anything else on the pod reading RCAGENT_SERVICE_KEY env after this phase (rc-sentry? other crates?)? Any cloud-side rc-agent that needs the same migration?
7. **Bootstrap-chicken-and-egg:** at very first boot after install, cache is empty, env may be unset. Does that leave a window where consumers 401 themselves? How long? Does the initial synchronous fetch in Plan 03 close this window?
8. **Observability:** if the cache fetch silently keeps returning 403 (wrong IP classification), what log line surfaces? Is that enough to alert James?
