# Canary procedure (pod 3) — end-to-end proof REQUIRED (B2 fix)

Pod 3 is the canary because:
- It's been a persistent problem pod (iRacing GL-8 signature per memory)
- Seeded ZL-1 / ZL-2 / INV-9 all reference pod 3 class bugs
- Medium-traffic — safer to canary than a heavy-traffic pod

**The end-to-end seeded-symptom test is REQUIRED.** CONTEXT.md specifies a concrete, non-disruptive method: launch AC with python.ini missing (ZL-2 pattern, ~30s, matches a seeded entry). No "DEFERRED for production observation" — the phase goal is that `check_audit_known_issues()` returns `Some(match)`, which can only be proven by seeing the match log line, not by inferring it from the cache read.

Steps on canary:
1. Delete HKLM key: `reg delete "HKLM\SYSTEM\CurrentControlSet\Control\Session Manager\Environment" /v RCAGENT_SERVICE_KEY /f` (via rc-sentry /exec)
2. Kill rc-agent to force RCWatchdog to restart it with no env inheritance: `taskkill /F /IM rc-agent.exe`
3. Wait 15s for RCWatchdog to respawn + rc-agent to do initial fetch
4. Grep rc-agent log for `Mesh key cache initial fetch ok` (Plan 03's synchronous log) AND/OR `periodic_refetch first_success resource="mesh_service_key"` — proof that fetch-from-server works without HKLM
5. Trigger the seeded symptom — the ZL-2 pattern is the non-disruptive choice:
   - Rename pod 3's `python.ini` to `python.ini.bak` via rc-sentry /exec
   - Launch AC via a staff-initiated game launch (use the standard `/games/launch` endpoint) — AC will fail to read python.ini, matching the seeded ZL-2 pattern
   - Wait 10s for the crash-detection path to reach `check_audit_known_issues()`
   - Restore `python.ini` from backup (the disruption is ~30s of one test launch)
6. Grep rc-agent log for `AUDIT KNOWN ISSUE matched` — this is the REQUIRED end-to-end proof that Tier 0 oracle works FROM CACHE (no HKLM, no env)
7. If step 6 fails, ROLLBACK canary: reg-add the HKLM value back (save it BEFORE deletion in step 1 so we can restore), kill rc-agent again, RCWatchdog restarts with env restored. Log the failure and HALT fleet expansion (Task 4 does not run).
