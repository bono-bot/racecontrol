# Phase 348: Auth Resilience — PLAN (Retroactive)

**Status:** CODE-COMPLETE (retroactive artifact)
**Milestone:** v47.0 Admin Dashboard Venue-Ready Hardening
**Planned:** 2026-04-10 | **Executed:** 2026-04-10

## Goal

Harden admin/staff authentication against brute-force attacks and provide emergency access when normal login is unavailable.

## Tasks

### 348-01: Per-IP + Per-Staff-ID Lockout
- Add `staff_login_attempts` DB table with indexes on `(staff_id, attempted_at)` and `(source_ip, attempted_at)`
- Implement per-IP in-memory lockout: 10 failures -> 15min lockout (matches kiosk_redeem_pin pattern)
- Implement per-staff-id DB lockout: 10 failures in 5min sliding window -> account lock
- Record every login attempt (success/failure) with source_ip, staff_id, timestamp
- **Files:** `crates/racecontrol/src/api/routes.rs`, `crates/racecontrol/src/db/mod.rs`

### 348-02: JWT + Multi-Device (SKIP)
- SC-3 (12h JWT): Already satisfied (24h lifetime)
- SC-4 (multi-device): Already satisfied (no session revocation)

### 348-03: Break-Glass Emergency Access
- Add `break_glass_secret` to AuthConfig in `config.rs`
- Implement `POST /api/v1/auth/break-glass` endpoint
- Issue 1-hour superadmin JWT with `staff_id="break-glass"`
- WhatsApp alert on both success and failure via Evolution API
- Return 404 if not configured (endpoint discovery prevention)
- Require `reason` field for audit trail
- **Files:** `crates/racecontrol/src/auth/admin.rs`, `crates/racecontrol/src/api/routes.rs`, `crates/racecontrol/src/config.rs`
