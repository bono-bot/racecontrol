```markdown
# Page: {Page Name}
**App:** web|kiosk  
**URL:** {baseUrl}{path}  
**Auth:** Required|None

## Expected Layout
- {What structural elements should be visible: nav, sidebar, cards, tables, headers}
- {Grid/layout pattern: e.g. "3-column card grid on desktop, single column on mobile"}

## Expected Data
- {What data should be populated: e.g. "Pod status cards for 8 pods", "Transaction table with date/amount/status columns"}
- {Dynamic content (from mask-config.ts): list what changes in real-time and should be ignored for layout comparison}

## Key Interactions
- {What should be clickable/interactive: buttons, links, filters, tabs}

## What "Wrong" Looks Like
- {Specific anomalies to flag: blank page, missing sidebar, 0 pods shown, error banner, login redirect, unstyled HTML}
- {Common failure modes from CLAUDE.md standing rules: e.g. "static files 404 = unstyled HTML with no JS"}
```

Use the mask-config.ts selectors to identify which elements are dynamic (timestamps, counters, live metrics) — these should be noted as "expected to change" in the Expected Data section, NOT flagged as anomalies.

For "What Wrong Looks Like", reference known failure modes from the codebase:
- Unstyled HTML (static files 404 from wrong outputFileTracingRoot)
- Login redirect loop (middleware protecting login page)
- Missing data (API returning empty arrays — server down or stale build)
- WebSocket disconnect indicator (red dot, "Connecting..." text)
- Error banners or exception screens

Keep descriptions concise — 15-30 lines per file. These are reference docs for AI comparison, not exhaustive specs.

Create `tests/page-audit/self-audit.sh` — a bash shell script that orchestrates the AI self-audit workflow:

**Step 1: Run page crawler on the 10 critical pages only.**
```bash
CRAWL_PAGES="/,/fleet,/billing,/billing/history,/sessions,/drivers,/games" CRAWL_APP=web \
  npx playwright test --config tests/page-crawler/playwright.config.ts 2>/dev/null

CRAWL_PAGES="/kiosk,/kiosk/staff,/kiosk/control" CRAWL_APP=kiosk \
  npx playwright test --config tests/page-crawler/playwright.config.ts 2>/dev/null
```

**Step 2: Find the latest screenshot for each critical page.**
For each page, find the most recent .png in `tests/screenshots/{app}/{sanitized_route}/`. The route sanitization matches crawl.spec.ts: leading slash removed, remaining slashes replaced with underscores, "/" becomes "root".

**Step 3: Generate audit-prompt.md.**
Create `tests/page-audit/audit-prompt.md` — a structured markdown file that Claude can use as instructions. Format:

```markdown
# Self-Audit: Page Review

For each page below, read the screenshot image and compare against the description.
Flag any anomalies — layout issues, missing data, error states, unexpected content.

## Page 1: Home (web /)
- Screenshot: tests/screenshots/web/root/{latest}.png
- Description: tests/page-audit/descriptions/web-home.md

## Page 2: Fleet (web /fleet)
...
```

**Step 4: Generate empty audit-report.md template.**
Create `tests/page-audit/audit-report.md` with header:
```markdown
# Page Audit Report
**Generated:** {ISO timestamp}
**Status:** PENDING — run self-audit review to populate

## Results
(To be filled by AI after reviewing screenshots against descriptions)
```

**Script requirements:**
- Must be executable (`chmod +x`)
- Accept optional `--skip-crawl` flag to skip Step 1 (use existing screenshots)
- Print summary: how many pages crawled, how many screenshots found, path to audit-prompt.md
- Exit 0 even if some pages fail to crawl (partial audit is better than no audit)
- Use `REPO_ROOT` derived from script location: `REPO_ROOT="$(cd "$(dirname "$0")/../.." && pwd)"`
- All paths relative to REPO_ROOT for portability
