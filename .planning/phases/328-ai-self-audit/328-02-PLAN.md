Create `~/.claude/hooks/self-audit-inject.js` — a UserPromptSubmit hook that injects a self-audit reminder at the START of frontend sessions.

**Detection logic:**
1. Read the user's prompt text from stdin (JSON with `{ session, userMessage }`)
2. Check if this is the first or second prompt in the session (use a state file `~/.claude/cgp-state/self-audit-prompted.txt` with session ID to avoid repeating)
3. Check if the prompt mentions frontend-related keywords: any of the FRONTEND_EXTENSIONS (.tsx, .jsx, .css), or keywords like "dashboard", "kiosk", "page", "UI", "frontend", "layout", "visual", "display", "billing page", "fleet page", "web app"
4. If both conditions met (early in session + frontend context), inject additionalContext

**Output format (UserPromptSubmit):**
```json
{
  "hookSpecificOutput": {
    "hookEventName": "UserPromptSubmit",
    "additionalContext": "SELF-AUDIT REMINDER: This session involves frontend work. Before making changes, run the page self-audit to establish baseline:\n\n```bash\nbash tests/page-audit/self-audit.sh\n```\n\nThen read tests/page-audit/audit-prompt.md and follow its instructions to review each page screenshot against its description. Write findings to tests/page-audit/audit-report.md.\n\nSkip this if you already ran self-audit this session."
  }
}
```

**Key implementation details:**
- State file tracks session ID to fire only once per session. Session ID from the input JSON's `session.id` field.
- On any error: `process.exit(0)` silently — never break Claude session.
- Do NOT trigger on non-frontend prompts (Rust, deploy, config, git-only).
- The hook file must be registered in `~/.claude/settings.json` under the hooks array. Read settings.json first, add the hook entry if not present, write back.

**Hook registration in settings.json:**
```json
{
  "event": "UserPromptSubmit",
  "hooks": [{
    "type": "command",
    "command": "node ~/.claude/hooks/self-audit-inject.js"
  }]
}
```

Check existing settings.json structure — it may already have UserPromptSubmit entries. Append to the existing hooks array, do not overwrite.

Add a new standing rule section to CLAUDE.md under Standing Rules > Process (after the existing process rules):

```markdown
### Self-Audit (v43.0)

- **Run page self-audit at frontend session start.** Before modifying any frontend code (tsx, jsx, css, Next.js pages), run `bash tests/page-audit/self-audit.sh` to capture current page screenshots and generate the audit prompt. Then read `tests/page-audit/audit-prompt.md` — for each page listed, use the Read tool to view the screenshot image and compare against the description file. Write anomalies to `tests/page-audit/audit-report.md`. This establishes baseline awareness: if a page is already broken before your changes, you know to fix it or avoid making it worse.
  _Why: Code-only fixes shipped 9+ times without anyone looking at the actual pages. The self-audit forces visual verification before AND after changes._
- **After frontend changes, re-run self-audit.** After completing frontend modifications, run `bash tests/page-audit/self-audit.sh` again and compare the new screenshots against descriptions. Any NEW anomalies introduced by your changes must be fixed before marking done.
  _Why: Without a post-change audit, regressions go undetected until a customer reports them._
```

Do NOT modify any other part of CLAUDE.md. Insert after the last entry in the "### Process" section, before the next `###` heading.
