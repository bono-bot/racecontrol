## Root cause hypothesis

The StartRCTemp silent-fail observed during the 2026-04-18 08:05 IST R1 recovery is caused by a **dual structural defect**:

**Defect 1 — Logon Mode / Run As User incompatibility with non-interactive context:** StartRCTemp runs as the `ADMIN` human-user principal with `Interactive only` logon mode (`<LogonType>InteractiveToken</LogonType>` in XML). When ADMIN is not interactively logged in (which was the case during R1 recovery — the recovery was being driven from James's workstation via rc-sentry /exec, with no active RDP/console session on the server), `schtasks /Run /TN StartRCTemp` returns `SUCCESS: Attempted to run` and exit code 0 but silently fails to launch the process. This is the **exact same failure mode** documented in `scripts/deploy/provision-startrcdirect.ps1` lines 12-18 as the reason StartRCDirect was created with `/RU SYSTEM /LO SERVICE`.

**Defect 2 — start-racecontrol.bat does NOT start racecontrol.exe directly:** Even if the schtask had fired successfully, the bat target (`C:\RacingPoint\start-racecontrol.bat` from Command 5) performs only (a) binary swap if a staged `racecontrol-????????*.exe` exists, (b) firewall rule refresh, (c) port-80 proxy setup, (d) launches `start-racecontrol-watchdog.ps1` via `start "" /B powershell`. **The bat file never executes `start racecontrol.exe` or equivalent.** Racecontrol is launched only as a side-effect of the watchdog script detecting that racecontrol is not running and then calling `schtasks /Run /TN StartRCDirect` itself (watchdog.ps1 line 111). So StartRCTemp is actually `StartRCTemp → start-racecontrol.bat → start-racecontrol-watchdog.ps1 → (eventually) schtasks /Run /TN StartRCDirect`. A chain of 4 hops with 2 failure modes (Defect 1 above, plus the Interactive-only watchdog spawn which also silently dropped).

StartRCDirect, in contrast, runs as SYSTEM with Interactive/Background logon mode, and its bat (`start-racecontrol-direct.bat`) directly launches racecontrol.exe. This is why R1 recovery succeeded when it fell back to StartRCDirect.

## Recommended option

**Option: A**

Retire StartRCTemp and use StartRCDirect exclusively. Evidence is conclusive: (1) StartRCTemp's Logon Mode (`Interactive only`) + Run As User (`ADMIN`, a human-user SID requiring an interactive logon token) is the same silent-no-op failure mode that `provision-startrcdirect.ps1:14` explicitly documents as the reason StartRCDirect was created to fix; (2) StartRCTemp's bat target (`start-racecontrol.bat`) does not directly launch racecontrol.exe at all — it only performs binary swap + watchdog spawn, so even a "working" StartRCTemp launch would be a 4-hop indirect chain that itself contains the same logon-mode failure in the watchdog PowerShell spawn. StartRCDirect has been proven to work (R1 recovery at 08:12 IST; watchdog.ps1:111 uses it for self-restart; it's SYSTEM/Interactive-Background so it works regardless of interactive session state). No rationale remains for keeping StartRCTemp in the deploy-server.sh startup path.
