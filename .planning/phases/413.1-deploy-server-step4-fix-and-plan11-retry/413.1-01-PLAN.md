# Locked decision (CONTEXT.md <specifics> Defect 1 — EXACT REPLACEMENT)

The current Step 4 swap line (deploy-server.sh line 246):
```
move /Y C:/RacingPoint/racecontrol-new.exe C:/RacingPoint/racecontrol.exe && echo SWAPPED || echo SWAP_FAILED_EL=!errorlevel!
```

MUST be replaced with the 4-line cmd.exe command block below (backslash paths, `%errorlevel%`, auto-recover guard):
```
del /Q C:\RacingPoint\racecontrol-prev.exe 2>nul
ren C:\RacingPoint\racecontrol.exe racecontrol-prev.exe || (echo SWAP_FAILED_EL=%errorlevel% & exit /b 1)
ren C:\RacingPoint\racecontrol-new.exe racecontrol.exe || (ren C:\RacingPoint\racecontrol-prev.exe racecontrol.exe & echo SWAP_FAILED_RECOVERED & exit /b 2)
echo SWAPPED
```

Note from CONTEXT.md: `ren racecontrol.exe racecontrol-prev.exe` works on a RUNNING process — Windows permits rename of locked executable, only delete is blocked. This is why the Step 3b `taskkill` + 3-second sleep already in the script is sufficient — by the time Step 4 runs, the process is dead but even if a stale handle remained, `ren` would still succeed.

# Why this plan does NOT touch Step 4's Bash-level `copy /Y ... racecontrol.exe racecontrol-prev.exe` preserve block (line 240)

The preserve block is functionally redundant with the new swap block (which itself renames the current racecontrol.exe to racecontrol-prev.exe before renaming racecontrol-new.exe to racecontrol.exe). Leaving the preserve `copy` in place is safe — it creates a same-name backup file that the new `del /Q racecontrol-prev.exe 2>nul` at swap-start wipes before the `ren` sequence runs. Result: no behavioral change from the preserve block; swap is authoritative.

# Why `exit /b 1` / `exit /b 2` are safe inside rc-sentry /exec

rc-sentry's `/exec` handler runs the cmd string under `cmd /C` — `exit /b N` sets the child cmd.exe's exit code, which rc-sentry surfaces as `exit_code` in the JSON response. The outer Bash check (`if ! echo "$SWAP" | grep -q "SWAPPED"; then fail ...`) already matches on stdout, not exit code. So `exit /b 1` on preserve failure will (a) skip printing SWAPPED, (b) surface `exit_code: 1` for diagnostics, (c) cause the outer Bash check to `fail "Swap failed..."` — correct behavior.
