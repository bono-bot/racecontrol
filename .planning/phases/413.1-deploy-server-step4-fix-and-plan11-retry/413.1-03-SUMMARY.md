**72h mtime-guarded cleanup of racecontrol-prev.exe in start-racecontrol.bat staged-binary branch via `forfiles /D -3`, plus preserve-if-not-exist safety on rename, hardening the CLAUDE.md OTA rollback window against the class of bat-level cleanup defects (defense-in-depth; R1 prev.exe disappearance remains un-traced).**

## Decisions Made

- **forfiles /D -3 for 72h window.** `forfiles` is a Windows built-in that self-cancels when no match — if prev is younger than 72h, the inner `del` never runs. Cheaper and more correct than explicit date arithmetic in batch.
- **Preserve-if-not-exist chain `if exist X if not exist Y ren X Y`.** Defends against a second entry into the staged branch (e.g. two staged binaries in one boot) where a fresh prev (created in the first entry) would otherwise be overwritten by a stale racecontrol.exe in the second entry.
- **ASCII-only via byte scan, not just `file` output.** `file` reported "Unicode text, UTF-8" after the initial edit — traced via `python3` byte iteration to two em-dashes (0xE2 0x80 0x94) in rem comments on lines 15 and 17. Replaced with `--`. Final `file` output: `DOS batch file, ASCII text, with CRLF line terminators`.
- **Narrative framed as defense-in-depth, NOT R1 fix.** The plan's own revision explicitly acknowledges the R1 prev.exe disappearance is NOT definitively traced to this code path (see Corrected Narrative section below). The 72h guard still applies because it's the ONLY bat-level del path for prev.exe — closing the class of defects where the bat COULD have been the culprit even if R1 was caused elsewhere.

## Corrected Causal Narrative (explicit per plan success criterion)

Plan 03 is **defense-in-depth** for the CONDITIONAL staged-binary branch in `start-racecontrol.bat`. The R1 recovery sequence (413-DEPLOY-EVIDENCE.md) observed `racecontrol-prev.exe` disappearing between Step 3c and Step 4-final; this is NOT definitively traced to `start-racecontrol.bat`:

- Line 14 is `if not defined STAGED goto :startrc`, making lines 15-16 a conditional block gated on a hash-named staged binary being present.
- In R1, `racecontrol-new.exe` was deleted at Step 3a BEFORE `StartRCTemp`/`StartRCDirect` ran — so the `dir /B /O-D racecontrol-????????*.exe` loop found no match, `STAGED` stayed empty, `goto :startrc` was taken, and the del+ren block was **skipped entirely**.
- Possible un-traced deletion paths (out of scope for Plan 03): (a) a watchdog/service running independently, (b) a `StartRCDirect`-triggered script, (c) a parallel session's cleanup.

Plan 03 still applies the 72h guard to the bat's conditional branch because:
1. It's the ONLY bat-level del path for `racecontrol-prev.exe`.
2. It's a cheap structural fix that closes the class of defects where the bat COULD have been the culprit (e.g. if a future deploy-server.sh stops pre-deleting `racecontrol-new.exe`, or if an operator manually stages a binary).
3. deploy-server.sh itself already uses atomic swap (Plan 01's pattern), so no change needed there.

**The R1 prev.exe disappearance anomaly remains an open investigation for a follow-up phase (413.2 or later).**
