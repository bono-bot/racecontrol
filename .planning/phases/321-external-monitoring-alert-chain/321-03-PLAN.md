<objective>
Add screenshot-based blanking verification to rc-sentry. After rc-agent is restarted and the blanking screen command is sent, rc-sentry uses Windows GDI GetPixel to sample 9 points on the screen and verify the blanking color (#1A1A1A) is actually displayed. If blanking fails, a WhatsApp alert is sent.

Purpose: Close the blind spot where rc-sentry says "restarted + blanked" but the screen shows something else (Edge failed to launch, wrong URL, etc.). This was a real incident in v17.0 where blanking was broken on all 8 pods for an unknown duration.
Output: New screen_verify.rs module, Cargo.toml feature additions, wiring in main.rs crash handler.
</objective>

    Create `crates/rc-sentry/src/screen_verify.rs` with the following structure:

    ```rust
    //! Screen blanking verification via Windows GDI pixel sampling.
    //!
    //! MON-05: After rc-agent restart, verify the blanking screen (#1A1A1A) is
    //! actually displayed by sampling 9 points on the virtual screen.
    //! Uses GetPixel() -- synchronous, ~1us per call, no bitmap allocation.
    //!
    //! Safe to call from Session 1 context (rc-sentry always runs in Session 1).
    //! Do NOT call from a polling loop -- cap at once per restart cycle.

    const LOG_TARGET: &str = "screen-verify";

    // Blanking color: #1A1A1A = Asphalt Black (brand identity)
    const EXPECTED_R: u8 = 26;
    const EXPECTED_G: u8 = 26;
    const EXPECTED_B: u8 = 26;
    const TOLERANCE: u8 = 10;
    const BLANKED_THRESHOLD_PCT: usize = 80; // 80% of points must match

    /// 9 sample points on a 1920x1080 screen.
    /// Distributed in a 3x3 grid avoiding edges (taskbar, window chrome).
    const SAMPLE_POINTS: &[(i32, i32)] = &[
        (100, 100),  (960, 100),  (1820, 100),   // top row
        (100, 540),  (960, 540),  (1820, 540),   // middle row
        (100, 980),  (960, 980),  (1820, 980),   // bottom row
    ];

    #[derive(Debug, Clone, PartialEq)]
    pub enum BlankingStatus {
        /// Screen appears blanked -- >= 80% of sample points match expected color.
        Blanked { matching_points: usize, total_points: usize },
        /// Screen is NOT blanked -- < 80% of sample points match.
        NotBlanked { matching_points: usize, total_points: usize },
        /// Could not determine (GDI failure, wrong session, etc.)
        Unknown(String),
    }
    ```

    Then implement `verify_blanking()`:

    **Production path (`#[cfg(not(test))]`):**
    1. Call `GetSystemMetrics(SM_CXVIRTUALSCREEN)` and `GetSystemMetrics(SM_CYVIRTUALSCREEN)` to get actual screen dimensions.
    2. Call `GetDC(std::ptr::null_mut())` to get the virtual screen DC. If null, return `BlankingStatus::Unknown("GetDC failed")`.
    3. Create an RAII guard struct that calls `ReleaseDC(null, hdc)` on drop to prevent DC leak.
    4. For each of the 9 sample points:
       - If point (x, y) exceeds screen dimensions, skip it (don't count toward total).
       - Call `GetPixel(hdc, x, y)`. If result is `CLR_INVALID` (0xFFFFFFFF), skip it.
       - Extract R = pixel & 0xFF, G = (pixel >> 8) & 0xFF, B = (pixel >> 16) & 0xFF.
       - If all three channels are within TOLERANCE of expected values, count as matching.
    5. Calculate percentage: `matching * 100 / valid_total`. If valid_total == 0, return Unknown.
    6. If percentage >= 80, return Blanked. Otherwise NotBlanked.

    **Test path (`#[cfg(test)]`):**
    Use a thread-local `RefCell<Vec<(i32, i32, u32)>>` to mock pixel values. Each test pushes `(x, y, colorref)` tuples. The test version of `verify_blanking()` reads from this mock instead of calling GDI.

    Write 6 unit tests:
    - `test_blanking_all_match`: Set all 9 points to RGB(26,26,26). Expect Blanked{9,9}.
    - `test_blanking_none_match`: Set all 9 points to RGB(255,255,255). Expect NotBlanked{0,9}.
    - `test_blanking_below_threshold`: Set 7 of 9 to match (77.7%). Expect NotBlanked{7,9}.
    - `test_blanking_at_threshold`: Set 8 of 9 to match (88.8%). Expect Blanked{8,9}.
    - `test_blanking_tolerance_boundary`: Set point to RGB(36,36,36) (exactly +10). Expect match. Set RGB(37,37,37) (+11). Expect no match.
    - `test_blanking_invalid_pixel_skipped`: Set a point to CLR_INVALID (0xFFFFFFFF). Verify it's excluded from both matching and total counts.

    **Step 4: Wire verify_blanking() into crash handler**

    In main.rs, find the crash handler thread (the loop that receives from `crash_rx`). After the restart is performed and the post-crash cooldown begins, add a blanking verification check:

    ```rust
    // MON-05: Verify blanking screen after restart
    // Wait 15 seconds for rc-agent to fully start and launch Edge
    std::thread::sleep(std::time::Duration::from_secs(15));
    let blanking = screen_verify::verify_blanking();
    tracing::info!(target: "watchdog", "Blanking verification after restart: {:?}", blanking);
    match &blanking {
        screen_verify::BlankingStatus::NotBlanked { matching_points, total_points } => {
            let msg = format!(
                "[rc-sentry] Pod {} blanking FAILED after restart! Only {}/{} points match expected color. Screen may not be blanked.",
                tier1_fixes::get_pod_id(), matching_points, total_points
            );
            tracing::warn!(target: "watchdog", "{}", msg);
            tier1_fixes::send_whatsapp_alert(&tier1_fixes::get_pod_id(), &msg);
        }
        screen_verify::BlankingStatus::Unknown(reason) => {
            tracing::warn!(target: "watchdog", "Blanking verification inconclusive: {}", reason);
        }
        screen_verify::BlankingStatus::Blanked { .. } => {
            tracing::info!(target: "watchdog", "Blanking verified successfully");
        }
    }
    ```

    IMPORTANT: The 15-second sleep is intentional -- rc-agent needs time to start, process the blank command, and launch Edge. This runs on the crash-handler thread, NOT the watchdog polling thread, so it does not block health checks. Cap this to once per restart cycle (the Cooldown state already prevents re-entry).

    No `.unwrap()` in production code. All GDI calls must be in `unsafe` blocks with null checks.
