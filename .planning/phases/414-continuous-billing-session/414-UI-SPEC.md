# Phase 414 — UI Design Contract

> Visual and interaction contract for the kiosk staff page changes that surface a paused-meter UI plus an idle-warning modal for continuous billing sessions. Generated by gsd-ui-researcher; verifies against gsd-ui-checker dimensions before executor implements.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | shadcn (already initialized) |
| Preset | shadcn `new-york`, baseColor `neutral`, CSS variables on, RSC + TSX, alias `@/components/ui` |
| Component library | shadcn primitives over Radix (Dialog, Button, Badge, Progress already vendored under `kiosk/src/components/ui/`) |
| Icon library | lucide (per `components.json` — already on disk via shadcn install) |
| Font | Montserrat (body, sans), Enthocentric (display headers — used in marketing surfaces, NOT inside this phase) |

**Source of truth for project tokens:** `kiosk/src/app/globals.css` (CSS variables `--rp-red`, `--rp-red-hover`, `--rp-grey`, `--rp-surface`, `--rp-border`) — Tailwind exposes them as `rp-red`, `rp-red-hover`, `rp-grey`, `rp-surface`, `rp-border` via `@theme inline` mapping. **DO NOT introduce raw hex values for these brand colors in new components — use the existing `rp-*` Tailwind classes.**

## Spacing Scale

Declared values (must be multiples of 4 — already enforced by Tailwind defaults; this phase reuses them):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px (gap-1, p-1) | Icon-to-label gaps, dot indicator beside text |
| sm | 8px (gap-2, p-2) | Compact element spacing inside the meter card |
| md | 16px (gap-4, p-4) | Default card padding (matches existing `LiveSessionPanel` cards) |
| lg | 20px (p-5) | Side panel outer padding (matches existing `LiveSessionPanel` shell `p-5`) |
| xl | 32px (p-8) | Modal inner padding (idle-warning dialog content) |
| 2xl | 48px | Not used in this phase |

**Exceptions:** Modal CTA stack uses `gap-3` (12px) which is the existing `ConfirmDialog` footer gap — kept for consistency, though not on the strict 8-pt scale. Acceptable per existing system.

## Typography

Reusing the existing kiosk typography stack — body text is Tailwind `text-sm` (14px) and `text-xs` (12px), section labels use uppercase tracking-wider, the meter readout uses `font-mono tabular-nums` (Roboto Mono fallback, already configured) for digit alignment.

| Role | Size | Weight | Line Height | Where used in this phase |
|------|------|--------|-------------|--------------------------|
| Display (meter readout) | 28px (text-3xl) | 700 (font-bold) | 1.1 (leading-none) | Cumulative cost amount, idle countdown timer |
| Heading (modal title) | 20px (text-xl) | 700 (font-bold) | 1.2 (leading-tight) | "Session ending soon" / "Insufficient balance" modal title |
| Subheading (status label) | 12px (text-xs) | 600 (font-semibold) + uppercase tracking-wider | 1.4 | "PAUSED — BETWEEN GAMES" pill, "SESSION TIME"/"ACTIVE"/"PAUSED" meter label |
| Body | 14px (text-sm) | 400 (font-normal) | 1.5 (leading-relaxed) | Modal description, secondary copy, button labels |

**Two weights only across the phase:** 400 (body) + 700 (numerals + headings). Existing kiosk uses 600 in some legacy semibold copy — we accept that as in-codebase convention but new copy in this phase uses 400 / 700 only.

**Mono numerals:** All driving time, cost, and countdown digits MUST use `font-mono tabular-nums` so the digits don't reflow when ticking. This is critical for staff glancing from across the room — non-tabular numerals produce visible character-width jitter.

## Copywriting Contract

| Element | Copy |
|---------|------|
| Paused meter status pill | `PAUSED — BETWEEN GAMES` (uppercase, tracking-wider, exactly this string — staff glances must match across pods) |
| Paused meter helper line | `Meter resumes when a new game starts` |
| Cumulative time label | `DROVE` (uppercase, matches existing `Drove {time}` line in `LiveSessionPanel`) |
| Cumulative cost label | `COST SO FAR` |
| Primary CTA in paused panel | `Continue with another game` (sentence case, verb-first, no period) |
| Secondary CTA in paused panel | `End session` (sentence case, lowercase verb to visually de-emphasize vs primary) |
| Empty-game-list state inside game picker (already exists) | unchanged — Phase 414 reuses `GamePickerPanel` as-is |
| IdleWarning modal title (Branch A — can continue) | `Still here?` |
| IdleWarning modal body (Branch A) | `Your session pauses at 15 minutes of inactivity. You have {N}s left and {credits} credits remaining.` (`{N}` is `seconds_remaining`; `{credits}` is `Math.floor(balance_paise/100)`) |
| IdleWarning modal primary CTA (Branch A) | `Tap to continue` |
| IdleWarning modal secondary CTA (Branch A) | `End session now` |
| IdleWarning modal title (Branch B — cannot continue) | `Out of credits` |
| IdleWarning modal body (Branch B) | `Your wallet ({credits} credits) cannot cover another minute. Please top up at the POS to continue, or end the session now.` |
| IdleWarning modal sole CTA (Branch B) | `End session` |
| Destructive End Session confirmation (REUSED — existing `ConfirmDialog`) | Title: `End this session?` Description: `The customer will be charged for time used. This cannot be undone.` Confirm: `End Session` (exact strings already in `kiosk/src/app/staff/page.tsx` — Phase 414 reuses unchanged) |
| Toast on successful continue | (none — re-entering the meter is its own confirmation) |
| Toast on End Session error | Reuse existing `commandErrors` toast pipeline (already in `useKioskSocket.ts`) — no new copy |

**Tone rules:**
- Second person ("Your session"), present tense.
- No exclamation marks anywhere in this phase.
- Numbers are concrete: `{N}s`, `{credits} credits` — never "soon" or "low".
- `credits` (lowercase) is the canonical PWA noun (per `feedback_credits_not_rupees.md`). Never write `Rs.`, `INR`, `rupees`, or `₹` in customer-facing kiosk copy.

### New (one new component, one new state branch)

| Component | File (new) | Why existing components do not suffice |
|-----------|-----------|-----------------------------------------|
| `IdleWarningDialog` | `kiosk/src/components/IdleWarningDialog.tsx` | `ConfirmDialog` is purpose-built for binary destructive confirmations (one title, one description, two static buttons). Wedging this into `ConfirmDialog` would balloon its prop surface. The new component still composes over `Dialog` / `DialogContent` / `Button` from `@/components/ui/*` — zero new shadcn primitives, zero new icons, ~120 LOC. |

**No other new components are introduced.** The paused-meter UI is a state branch inside the existing `LiveSessionPanel`, not a new file.

### Component Spec — `IdleWarningDialog`

```tsx
interface IdleWarningDialogProps {
  // Null when no warning active. Set when DashboardEvent::IdleWarning arrives.
  warning: {
    pod_id: string;
    session_id: string;
    balance_paise: number;
    seconds_remaining: number;  // server-pushed; component locally interpolates 1s downward
    can_continue: boolean;
  } | null;
  podNumber?: number;            // for "POD 03" subtitle line
  onContinue: (podId: string) => void;  // opens game picker for that pod
  onEndSession: (sessionId: string) => void;  // routes through existing handleEndSession (which itself opens the destructive ConfirmDialog)
  onDismiss: () => void;          // local-only dismiss (e.g. if a game starts, parent unmounts the modal)
}
```

**Layout (Branch A — can_continue = true):**
```
+--------------------------------------------------------+
|  [DialogContent — bg-[#1A1A1A] border-rp-border]       |
|                                                        |
|  POD 03                                  ← text-xs rp-grey, tracking-wider
|  Still here?                             ← text-xl text-white font-bold
|                                                        |
|  [Countdown ring: 28px font-mono red when <30s,        |
|   amber when 30-60s, white when >60s]                  |
|       2:43                                             |
|                                                        |
|  Your session pauses at 15 minutes of inactivity.      |
|  You have 163s left and 245 credits remaining.         |
|                                                        |
|  [ Tap to continue        ]   ← bg-rp-red, full width primary
|  [ End session now        ]   ← outline border-rp-border text-rp-grey
+--------------------------------------------------------+
```

**Layout (Branch B — can_continue = false):**
```
+--------------------------------------------------------+
|  POD 03                                                |
|  Out of credits                          ← text-xl text-white font-bold
|                                                        |
|       2:43                                             |
|                                                        |
|  Your wallet (12 credits) cannot cover another         |
|  minute. Please top up at the POS to continue, or      |
|  end the session now.                                  |
|                                                        |
|  [ End session            ]   ← border-2 border-rp-red text-rp-red full width
+--------------------------------------------------------+
```

**Behavior:**
- The dialog is modal (uses shadcn `Dialog` with `open={warning !== null}`), occupies center of viewport, blurs background per existing dialog overlay styling.
- Countdown decrements locally every 1s via `setInterval` (matching the existing `LiveSessionPanel` local-interpolation pattern). Server may re-broadcast `IdleWarning` with refreshed `seconds_remaining` — component resets to that value on prop change.
- When `seconds_remaining` reaches 0, dialog stays mounted (auto-end fires server-side and the session disappears from `billingTimers` — parent unmounts the dialog naturally).
- `onContinue` triggers: dismiss the dialog locally, set `selectedPodId` to `warning.pod_id`, set `panelMode` to `"game_picker"` so the side panel opens to the existing game picker.
- `onEndSession` triggers: route through `handleEndSession(session_id)` which already opens the destructive `ConfirmDialog`. The IdleWarningDialog dismisses itself before opening that confirmation (avoids stacked modals).

### Component Spec — Paused-meter UI inside `LiveSessionPanel`

The existing meter card in `LiveSessionPanel` (lines 173-211) currently renders one of: `paused_manual`, `waiting_for_game` (initial), `paused_game_pause`, `paused_crash_recovery`, `paused_disconnect`, or default ("Session Time"). Add a new branch:

**Trigger:** `billing.status === "waiting_for_game" && (billing.elapsed_seconds ?? 0) > 0`

**Renders (replaces the "GAME LOADING" label and progress bar of the existing waiting branch):**
- Status pill replaces the small uppercase label: `<span className="text-xs font-semibold uppercase tracking-wider text-rp-grey">PAUSED — BETWEEN GAMES</span>`
- The big numeric readout shows **cumulative cost** in credits (NOT remaining time): `<span className="text-3xl font-bold font-mono tabular-nums text-white">{(billing.cost_paise / 100).toFixed(0)} cr</span>` — frozen, not ticking.
- Helper line below readout: `<p className="text-xs text-rp-grey">Drove {formatTime(billing.driving_seconds)} so far · Meter resumes when a new game starts</p>`
- Progress bar: hidden in paused state (no allocated countdown visualizes meaningfully).
- A new button stack BELOW the meter card, ABOVE the existing controls row:

```tsx
<div className="grid grid-cols-1 gap-3">
  <button
    onClick={() => onLaunchGame?.(pod.id)}
    className="py-4 bg-rp-red hover:bg-rp-red-hover text-white font-semibold rounded-xl text-base transition-colors"
  >
    Continue with another game
  </button>
  <button
    onClick={() => onEndSession(billing.id)}
    className="py-3 border-2 border-rp-red text-rp-red hover:bg-rp-red hover:text-white font-semibold rounded-xl text-sm transition-colors"
  >
    End session
  </button>
</div>
```

The existing bottom controls (Pause/Resume/+10 min/End Session in the existing component) remain present but the End Session button there becomes redundant in the paused-between-games state — the new button stack supersedes it. Executor decision: hide the redundant bottom End Session button when the new branch is active. This avoids two End Session buttons on the same panel.

## Accessibility (kiosk-specific — touch-first, glance-readable)

This is a touch kiosk operated by staff who often glance from across the room. Standard web a11y rules apply, plus venue-specific ones:

| Concern | Spec |
|---------|------|
| **Touch target size** | Every interactive element in this phase MUST be at least 44x44 CSS px. The "Continue with another game" button is `py-4` (32px vertical padding + ~24px line height = ~56px tall) — passes. The "End session" button is `py-3` (24px + line height = ~44px) — at the floor. Modal CTAs use shadcn `Button size="lg"` (`h-11 px-8`) — passes (44px+). |
| **Glance contrast** | Every text-on-bg pair in this phase must have ≥ 4.5:1 contrast (WCAG AA). White on `#1A1A1A` = 17.6:1, `text-rp-grey` (`#5A5A5A`) on `#1A1A1A` = 3.5:1 (FAILS body, OK for incidental labels). **For the paused-state body copy ("Drove X so far · Meter resumes...") we accept rp-grey because it is incidental subtext; the key info — pill label, cost amount, button labels — is white or red on dark bg.** |
| **Color is not the only signal** | The `PAUSED — BETWEEN GAMES` state is conveyed by both color (grey) AND text. The countdown urgency is conveyed by both color (white → amber → red) AND the decreasing number. Branch A vs Branch B of the modal differs in BOTH colors AND text — Branch B's title literally says "Out of credits". |
| **Motion** | Countdown ticking is 1s/step (not animated, not pulsing). The only animations in this phase: the existing `pulse-dot` for active driving state (already in code) and the standard shadcn dialog enter/exit fade. No flashing, no rapid color cycling. |
| **Modal focus trap** | shadcn `Dialog` already implements focus trap, ESC dismiss, and `aria-modal` — IdleWarningDialog inherits these. The primary CTA receives focus on open (set `autoFocus` like `ConfirmDialog` does today). |
| **Live region for countdown** | Countdown SHOULD have `aria-live="polite"` so screen readers announce the changing time without being disruptive. Acceptable to omit if executor finds Radix conflicts; this is a kiosk, not a screen-reader-primary surface. |
| **Touch dwell** | NO confirmation-on-hover patterns. All actions are click/tap commit. Long-press is not used anywhere in the kiosk and Phase 414 does not introduce it. |
| **Glance distance** | Cumulative cost amount uses `text-3xl` (28px) — readable from ~3m at 1080p kiosk display. Countdown timer in modal uses `text-3xl` for same reason. Pill label uses `text-xs` (12px) only because it's chromatic context, not actionable info. |

## Acceptance Criteria (gsd-ui-checker + gsd-ui-auditor will verify these)

- [ ] **AC-1 Paused trigger correctness:** When `billing.status === "waiting_for_game"` AND `billing.elapsed_seconds > 0`, the paused-meter branch renders. When `billing.status === "waiting_for_game"` AND `billing.elapsed_seconds === 0`, the existing `LaunchTimerBanner` initial-wait UI renders unchanged.
- [ ] **AC-2 Cumulative cost is frozen:** In the paused branch, the cost number does NOT tick. It equals the value of `billing.cost_paise` at the moment of the pause and updates only when a new `billing_tick` arrives (which itself only fires on Active).
- [ ] **AC-3 PAUSED pill rendered:** The string `PAUSED — BETWEEN GAMES` (with em-dash, uppercase, tracking-wider) appears as the meter status label in the paused branch.
- [ ] **AC-4 Continue button uses brand red:** "Continue with another game" button is `bg-rp-red` solid, white text, `font-semibold`, ≥44px tall, full width inside the side panel.
- [ ] **AC-5 End session button is outlined red:** "End session" button uses the existing `border-2 border-rp-red text-rp-red hover:bg-rp-red hover:text-white` pattern (matches the existing bottom End Session button styling).
- [ ] **AC-6 Continue routes to game picker:** Tapping "Continue with another game" sets `panelMode = "game_picker"` for the same `selectedPodId` — no new panel mode is introduced.
- [ ] **AC-7 End session triggers existing confirmation:** Tapping "End session" routes through the existing `handleEndSession(billing.id)` path which opens the existing `ConfirmDialog` ("End this session?" — exact copy reused).
- [ ] **AC-8 IdleWarningDialog renders on event:** When `useKioskSocket` receives `DashboardEvent::IdleWarning`, the new `IdleWarningDialog` mounts and is centered on screen with the shadcn dialog overlay backdrop.
- [ ] **AC-9 Countdown ticks locally:** The countdown displayed inside the modal decrements by 1 every 1s, regardless of WebSocket tick rate. On every new IdleWarning event, the local counter resets to the server-provided `seconds_remaining`.
- [ ] **AC-10 Branch A copy + CTA:** When `can_continue === true`, modal title is `Still here?`, body matches the spec template with `{N}` and `{credits}` substituted, primary CTA is `Tap to continue` (red, solid), secondary CTA is `End session now` (outlined grey).
- [ ] **AC-11 Branch B copy + CTA:** When `can_continue === false`, modal title is `Out of credits`, body references the wallet credit count, the SOLE CTA is `End session` (outlined red). No "continue" button is rendered.
- [ ] **AC-12 No deprecated orange:** `grep -rn "#FF4400\\|orange-4\\|orange-5\\|orange-6" kiosk/src/components/IdleWarningDialog.tsx` returns zero hits. Same for the paused-branch additions in `LiveSessionPanel.tsx` (only existing `bg-orange-900/50` on the unchanged disconnected-pod banner is allowed).
- [ ] **AC-13 No new color tokens:** No new `--*` CSS variables introduced. No new hex literals beyond what already exists in `globals.css` and the existing kiosk tailwind palette (Tailwind utility classes from the default neutral/amber/red ramps are acceptable).
- [ ] **AC-14 Touch targets:** Every interactive element added by Phase 414 measures ≥44px on the dominant axis when rendered at 1x in a 390-wide viewport (kiosk reference).
- [ ] **AC-15 Mono numerals:** Cost amount, driving time, and countdown timer all use `font-mono tabular-nums`.
- [ ] **AC-16 Modal focus + ESC:** IdleWarningDialog focus-traps on open, primary CTA is auto-focused, ESC dismisses (Branch A only — Branch B should still allow ESC since End Session is not destructive at this point; the destructive confirm comes from the routed-through `ConfirmDialog`).
- [ ] **AC-17 Coexistence:** The IdleWarningDialog renders ON TOP of the paused-meter side panel — both are visible (the dialog overlay dims the meter behind). Closing the dialog reveals the paused-meter UI underneath, NOT a blank page.
- [ ] **AC-18 No layout shift on swap:** Switching from Active meter to Paused meter and back must not change the side-panel width or shift the pod grid behind it. Both states render inside the same `SidePanel` shell.
