## Audit Result Tables

### Lock Discipline Audit — PASS with one note

All Phase 414-specific code correctly drops locks before `.await` calls:
- `idle_warnings_to_emit` populated inside lock, processed after `drop(timers)` → correct
- `phase414_idle_auto_ends` populated inside lock, processed after lock drop → correct
- `handle_game_off` drops `timers` before `waiting_for_game.write().await` → correct
- `handle_live_resume` drops `timers` write lock in `{ }` block before `sqlx::query_scalar` `.await` → correct

Pre-existing dual-lock pattern at billing_timer.rs:468-469 is MMA-2 (P1-B), tracked but not blocking.

### Financial Correctness Audit — PASS

Core property preserved: `elapsed_seconds` accumulates only while `status == Active`. The `WaitingForGame` tick branch increments `between_games_idle_seconds` but does NOT increment `elapsed_seconds`. `snap_debit_amount()` reads `self.elapsed_seconds` which is frozen during WaitingForGame.

INTEGRATION-01 (`cumulative_snap_25_5_yields_pkg_30`) explicitly verifies frozen-then-resumed accumulation.

No UPDATE-then-SELECT-same-column trap found in auto-end or stop_billing paths. CAS UPDATE in `authoritative_end_session` writes `driving_seconds` from a snapshot taken before the query.

stop_billing elapsed_seconds read prefers in-memory (most accurate) over DB (synced every 60s). No corruption vector.

### FSM Transition Completeness — PASS

3 Phase 414 rows internally consistent:
- `Active + GameStopped → WaitingForGame` — no collision
- `WaitingForGame + End → Completed` — does not conflict with existing `Cancel → CancelledNoPlayable` or `GameLive → Active`
- `WaitingForGame + EndEarly → EndedEarly` — clean

Pre-existing `PausedManual + EndEarly` gap is MMA-4 (P2), not Phase 414 introduced.

`WaitingForGame + Disconnect` intentional absence documented at billing_fsm.rs line 121.

### Backwards Compatibility — PASS

`between_games_idle_seconds: Option<u32>` with `#[serde(default, skip_serializing_if = "Option::is_none")]`. Old clients deserialize via serde default. Test at types.rs line 1688-1691 confirms old-client JSON case explicitly. No breaking change.

### UI Spec Compliance — PASS

IdleWarningDialog correctly distinguishes Branch A (`can_continue: true`) and Branch B (`can_continue: false`). Countdown uses `setInterval` keyed to `warning` identity — no stale-closure bug. `onDismiss` callback clears modal without triggering `onEndSession` — correct (dismissal ≠ ending).

`onContinue` handler at staff/page.tsx:731-735 sets `selectedPodId` and opens game picker — correct UX intent.

Note: dismissing the modal without choosing leaves session in WaitingForGame with auto-end clock still running. Modal won't reappear (server-side one-shot). Document in runbooks.

### Concurrent Edge Cases — PASS

- Pod offline mid-stream WaitingForGame: existing disconnect detection runs only when `timer.status == Active`. WaitingForGame branch uses `continue` before the offline check. Meter is already frozen, no double-billing. The 15-min idle window will still fire via `phase414_idle_auto_ends`. Customer-favourable behavior.
- Two rapid GameStopped events: second call gets `WaitingForGame + GameStopped` → no table entry → `validate_transition` returns `Err` → logged WARN, no state mutation. Correctly idempotent.

### Test Coverage — PASS

INTEGRATION-01..04 + TIMER-01..04 cover the correct paths. INTEGRATION-04 uses SQL-level CAS shapes (mirrors production) but does not exercise the actual `stop_billing` HTTP handler. Acceptable for pre-deploy gate; tracked for nyquist audit.
