**cloud_sync.rs — add `pull_tables_now` (filtered pull function):**

Add `pub(crate) async fn pull_tables_now(state: &Arc<AppState>, tables: &[&str]) -> anyhow::Result<()>` after the existing `sync_once_http` function (~line 1050). This function:

1. Gets the cloud URL from `state.config.cloud.api_url` — return `Err(anyhow!("cloud_url not configured"))` if None.
2. Builds a comma-separated table list from the `tables` parameter (NOT from `SYNC_TABLES` constant — this is the filtered version).
3. Makes the same HTTP GET request as `sync_once_http` but with only the requested tables in the `tables` query param.
4. Parses the JSON response and performs the same upsert logic as `sync_once_http`, but only for the tables present in the response.
5. Uses the existing `http_client` from the AppState or creates a reqwest client (follow whatever `sync_once_http` does).
6. Does NOT update the `last_synced` timestamp (this is an out-of-band pull, not a regular sync cycle).

Per D-08/D-09, this function is called by both `sync_pull_now_handler` and `change_staff_pin_safe`.

**routes.rs — add `change_staff_pin_safe` handler:**

Add after `reset_staff_pin` (~line 13390). Follow the exact signature pattern of `reset_staff_pin`. Per D-06/D-07/D-08:

```rust
async fn change_staff_pin_safe(
    State(state): State<Arc<AppState>>,
    Path(id): Path<String>,
    headers: axum::http::HeaderMap,
    Json(req): Json<ChangePinRequest>,
) -> impl IntoResponse {
```

Implementation per D-08 orchestration sequence:
1. Generate `correlation_id` via `uuid::Uuid::new_v4().to_string()`.
2. Validate PIN: `req.new_pin.len() < 4 || !req.new_pin.chars().all(|c| c.is_ascii_digit())` -> return 400 with `"PIN must be 4+ numeric digits"` and correlation_id.
3. Check if this instance is venue: `let is_cloud = crate::config::this_instance_is_cloud(&state.config);` (check the existing function — if it doesn't exist, check `state.config.cloud.is_cloud` or equivalent pattern used in `cloud_authority_guard`).
4. If venue (not cloud):
   - Get cloud URL from `state.config.cloud.api_url` — return 503 if None.
   - Extract Bearer token from `headers.get("authorization")` — clone the string value.
   - Build reqwest POST to `{cloud_url}/api/v1/admin/staff/{id}/change-pin` with the same Bearer header and `{"new_pin": req.new_pin}` JSON body.
   - Call `.send().await` then `.error_for_status()` — on failure, return 502 with `"Cloud PIN change failed: {error}"`.
   - Parse response as `ChangePinResponse` — extract `cloud_verified`.
   - IMPORTANT: Do NOT hold any lock across the `.await` — clone all needed values before the request.
5. If cloud:
   - Check `cloud_authority_guard(&state, "staff_members")` — should NOT return rejection on cloud (it guards venue writes, cloud is authoritative). If it does reject, pass through.
   - `UPDATE staff_members SET pin = ?, updated_at = datetime('now') WHERE id = ?` using `sqlx::query`.
   - Call `post_write_verify_staff_pin(&state.db, &id, &req.new_pin).await` — set `cloud_verified` based on result.
6. Trigger immediate sync: `cloud_sync::pull_tables_now(&state, &["staff_members"]).await` — log warning on failure but don't fail the whole operation.
7. Verify venue PIN: `venue_verified = post_write_verify_staff_pin(&state.db, &id, &req.new_pin).await.is_ok()`.
8. Spawn delayed verify: `spawn_delayed_sync_verify(state.db.clone(), state.config.cloud.sync_interval_secs, id, req.new_pin, correlation_id.clone())`.
9. Return `ChangePinResponse` with `status: if cloud_verified && venue_verified { "ok" } else { "partial" }`.
